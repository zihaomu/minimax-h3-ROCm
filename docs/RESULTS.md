统一工作量：1344×768、124帧、24fps、10步、带音频；保持fresh文本编码、原预览和MP4保存。
当前main已完成真实输入回放及Standard工程对照；原C1精度门未通过，历史正式成绩保持。

| 方案 | 完整热运行耗时 | 结果范围 |
|---|---:|---|

上述历史本机三项均按1次完整预热 + 3次热运行记录，中位不包含预热；没有选取最快单次充当成绩。
191秒来自历史优化实现，不能直接当作当前main的速度承诺。BR512与191秒记录不构成同窗口的配对加速比。

[机器可读摘要](results.json)只保存关键配置、数字、资格范围和原始记录SHA。
完整日志、输出、逐层误差、profile、参数明细与探索笔记保存在本地vibe / archive，不随GitHub同步。

当前默认attention为reduced_error；其他INT8 / FP8 / Triton / SDPA为显式控制。当前正式资格仍需通过原C1门。


## 当前源码：单双卡工程对照（2026-11-11）

源码 `7e283279`，reduced_error / 7 heads / BR128，相同Standard配置、权重、prompt与seed；保留fresh TE、10 NFE、动态预览、音频和MP4保存。

| 模式 | 三次有效热运行（秒） | 热运行中位（秒） |
|---|---|---:|
| 单R9700，同数学路径对照 | 474.085 / 880.113 / 1761.529 | **880.113** |
| 双R9700，当前main | 211.453 / 220.585 / 213.710 | **213.710** |

端到端中位耗时比 **4.118×**，耗时减少 **75.72%**。
单卡通过[基准适配器](../tools/standard_single_adapter.py)在一张卡上顺序执行相同两个28-head分支，保留token分区和INT8量化边界。基准wrapper先调用当前节点的 `_reserve_activation_memory(model)`，再调用适配器 `install(model)`；首forward采用同样的8GiB预算和force_full_load。
AV latent与完整FP32解码像素跨模式逐元素/字节相同；音频VAE解码waveform跨模式relative L2为1.51e-6（0.000151%），各模式内完全重复；有效输入、noise/sigmas、计数、媒体与资源门通过。

单卡第3轮曾被外部GPU0进程打断；保留前两次完整热运行，重新完整预热后补第3次。
因此单卡3次有效热测来自**2个会话、2次完整预热**，双卡为同会话1次预热+3热测；受干扰半轮与全部预热均未计入中位。
本轮存在较大单卡耗时波动，窗口未交错采集；这是当前软件路径的工程耗时比，不能据此判断纯硬件扩展效率或充分调优的单卡上限。

原生单卡控制另测中位1187.950秒，但其block数学/量化边界与双卡不同，最终AV latent也不等价，未用它计算上述比值。
两种当前路径对合格原C1参考的video/audio relative L2约40.05% / 10.23%，原1%门未通过；未替换284.681秒历史正式成绩。
完整原始日志、视频和恢复验收证据保存在本地研究入口，不上传GitHub。


## 仅 SwiGLU 默认接入：双卡工程对照（2026-11-12）

GPU5+6，同源码、同 Standard 配置，原路径与仅 SwiGLU 融合各 1 次完整预热＋3 次热运行；关闭 trace、逐 block profile 和激活审计。ConvRot256、行量化、GEMM、attention 均保留原实现。

| 路径 | 三次热运行（秒） | 中位（秒） |
|---|---|---:|
| 原 eager SwiGLU | 205.910 / 205.133 / 219.442 | **205.910** |
| 仅融合 SwiGLU，现默认 | 222.331 / 220.019 / 208.174 | **220.019** |

本轮融合批次中位比原路径多 **14.109 秒 / 6.85%**，没有证实端到端收益。两批顺序执行，存在首步及去噪波动，不能把差值全部归因为该算子。此前 fc2 局部微基准的收益不能推广成整个模型的收益。

有效输入、AV latent 和编码前完整 FP32 视频像素跨路径按字节相同；每路径内部输出重复、资源及媒体门通过。跨路径音频 VAE waveform relative L2 为 **2.05e-6**，严格波形字节门未过；最终有损 MP4 也不逐位相同。两 rank 短请求各 250 次 activation 逐位审计通过，完整计时中每 rank 每请求 2500 次融合调用、审计关闭。原 C1 门仍未过，本轮只记工程成绩；历史正式和历史最佳工程成绩保留原资格。
