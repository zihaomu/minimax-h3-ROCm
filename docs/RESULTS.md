# MiniMax H3：关键结果

统一工作量：1344×768、124帧、24fps、10步、带音频；保持fresh文本编码、原预览和MP4保存。
**以下是已有历史记录，整理后的当前main尚未重新完成GPU / Standard验收。**

| 方案 | 完整热运行耗时 | 结果范围 |
|---|---:|---|
| 单张RTX5090公开记录 | **85.230秒** | 发布者报告，本机未重测 |
| 双R9700历史正式合并版本 | **284.681秒** | 原数值与媒体门通过；当轮匹配基线372.505秒，约1.309× |
| 双R9700历史最佳工程版本：BR128 + native_norm_rope | **191.438秒** | 工程中位；原C1正式精度门未通过 |
| 双R9700历史BR512工程版本 | **230.806秒** | 工程中位；原C1正式精度门未通过，卡对和运行窗口不同 |

本机三项均按1次完整预热 + 3次热运行记录，中位不包含预热；没有选取最快单次充当成绩。
191秒来自历史优化实现，不能直接当作当前main的速度承诺。BR512与191秒记录不构成同窗口的配对加速比。

5090来源为发布者的[固定版本记录](https://github.com/ChrisJohnson89/minimax-h3-comfyui/tree/0409aa4b18767cd7d18de66442671e6dfe7f2ea4)。
公开记录的精确attention / 缓存细节未完全核实，表中不据此宣称同精度的硬件性能胜负。

[机器可读摘要](results.json)只保存关键配置、数字、资格范围和原始记录SHA。
完整日志、输出、逐层误差、profile、参数明细与探索笔记保存在本地vibe / archive，不随GitHub同步。

当前默认attention为reduced_error；其他INT8 / FP8 / Triton / SDPA为显式控制。下一次正式速度更新需先完成当前源码的真实输入回放与完整Standard资格。
